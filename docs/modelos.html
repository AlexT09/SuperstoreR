Modelos y resultados

7 modelos de regresión evaluados en 2017, un año que no vieron al entrenar

Entrenamiento de los modelos

Aquí se entrenan los 7 modelos con el mismo procedimiento de model/train_model.R: los datos se separan en el tiempo (entrenamiento 2015–2016 y prueba 2017), cada modelo busca sus mejores hiperparámetros con Grid Search y validación cruzada temporal, y se evalúa una sola vez en 2017. El código está a la vista y comentado; tarda alrededor de 20 segundos.

1. Datos del modelo

# Funciones del entrenamiento: los 7 modelos con sus rejillas (model/modelos.R), las métricas
# (model/evaluate.R) y la validación cruzada temporal (model/entrenamiento.R)

panel <- load_mensual()

# Agrega las variables del modelo (todas usan solo meses anteriores, model/features.R) y el
# objetivo: el índice = ventas del mes ÷ promedio de los 12 meses anteriores.
# Se descartan las filas sin 12 meses de historia (todo 2014).

3. Entrenamiento con Grid Search y evaluación en 2017

busquedas <- list()
filas <- list()
for (nombre in names(MODELOS)) {
  rejilla <- MODELOS[[nombre]]$rejilla
  t0 <- Sys.time()

  # Grid Search: para cada combinación de la rejilla, entrena en cada pliegue y mide el MAE del
  # índice en sus 3 meses de validación; el error de la combinación es el promedio de los 4 pliegues
  error_cv <- sapply(seq_len(nrow(rejilla)), function(j) {
    combinacion <- rejilla[j, , drop = FALSE]
    mean(sapply(cv, function(f) {
      # ajustar_modelo() ajusta el preprocesamiento (one-hot + estandarización) y el modelo solo
      # con los meses de entrenamiento del pliegue, como un Pipeline de scikit-learn
      modelo <- ajustar_modelo(nombre, combinacion, train[f$train, ])
      mean(abs(train[[TARGET]][f$valid] - predecir_indice(modelo, train[f$valid, ])))
    }))
  })

  # La combinación con menor error de validación se reentrena con todo 2015–2016
  mejor <- which.min(error_cv)
  final <- ajustar_modelo(nombre, rejilla[mejor, , drop = FALSE], train)
  segundos <- as.numeric(difftime(Sys.time(), t0, units = "secs"))
  busquedas[[nombre]] <- list(final = final, cv = error_cv[mejor], params = rejilla[mejor, , drop = FALSE])

  # Evaluación en 2017, que el modelo no vio: el índice predicho se convierte a dólares
  pred <- a_ventas(predecir_indice(final, test), test)
  m <- metricas(test$Sales, pred)
  filas[[nombre]] <- tibble(
    Modelo = nombre,
    `Error de validación (MAE del índice)` = sprintf("%.4f", error_cv[mejor]),
    `MAE 2017` = usd(m$MAE), `RMSE 2017` = usd(m$RMSE), `R² 2017` = sprintf("%.2f", m$R2),
    `Mejores hiperparámetros` = fmt_params(a_json(as.list(rejilla[mejor, , drop = FALSE]))),
    Segundos = sprintf("%.1f", segundos)
  )
}

# Referencia para comparar: vender lo mismo que el mismo mes del año anterior (lag_12)
ref_m <- metricas(test$Sales, test$lag_12)
filas[[REFERENCIA]] <- tibble(
  Modelo = REFERENCIA, `Error de validación (MAE del índice)` = "—",

)

4. Elección del mejor modelo

# El mejor modelo es el de menor error de validación cruzada. La prueba de 2017 no interviene en la
# elección: así sigue siendo una medida independiente del error. El árbol de decisión individual se
# compara, pero no puede ser el modelo final porque es inestable (NO_ELEGIBLES, model/entrenamiento.R).

Resumen

  • Mejor modelo: Random Forest, elegido por validación cruzada (Grid Search).
  • MAE en 2017: $2,697, un 7 % menos error que la referencia ($2,912).

  • Desvío del total 2017: +2.1 % (referencia: -16.9 %).

Ranking de modelos (MAE en 2017)

Los modelos con la barra a la izquierda de la línea superan a la referencia. Las diferencias entre ellos son pequeñas (de $2,511 a $3,389): con 288 filas de entrenamiento, la señal disponible es sobre todo la estacionalidad, y todos la capturan. Random Forest (en verde) se eligió por su error de validación cruzada, antes de mirar 2017. SVR tuvo el menor MAE entre los elegibles en 2017 ($2,511) y no se eligió porque elegir mirando 2017 haría que esa prueba dejara de ser independiente: en validación cruzada su error fue 0.643, contra 0.616 de Random Forest. El árbol de decisión se entrena y se compara, pero no es elegible como modelo final: un solo árbol es inestable (cambios mínimos en los datos cambian sus cortes); para eso están sus versiones estables, Random Forest y XGBoost.

¿Hay sobreajuste? Error en entrenamiento vs. prueba

Un modelo sobreajustado se equivoca poco con los datos que vio y mucho con los nuevos. Sin brecha relevante (1 punto o menos): Lasso, Ridge y la referencia. La mayor brecha es la de Árbol de decisión (42 % → 67 %), de los modelos más flexibles, que memorizan parte del entrenamiento. Random Forest pasa de 39 % a 53 %, y en 2017 sigue por debajo de la referencia (57 %). La validación cruzada mide el error en meses no vistos, así que al elegir el modelo ya tiene en cuenta este efecto.

Importancia de variables (Random Forest)

Importancia por permutación en 2017: cuánto aumenta el error si se desordena cada variable. Dominan el mes del año y las ventas del mismo mes del año anterior, es decir, la estacionalidad que mostró el EDA. Región, Categoría y Ventas del mes anterior (relativas) tienen importancia cero o negativa: desordenarlas no empeora el modelo, o sea que no aportan información útil en 2017. Categoría y región pesan poco porque el índice ya pone cada serie en su propia escala.

¿Cuánto confiar en la proyección de un año completo?

  • Desvío del total anual: +4.4 % (referencia: -16.9 %).
  • Error del total mensual: 18.7 % ($11,431 por mes en promedio).
  • R² del total mensual: 0.62.

2017 proyectado solo con datos hasta 2016

Es la misma forma en que se proyecta 2018: cada mes proyectado se usa como historia del siguiente, sin conocer ningún dato real del año. El modelo acierta el total del año y la forma estacional; los errores están en el detalle de cada mes. La referencia subestima todo el año porque repite 2016 sin el crecimiento.
